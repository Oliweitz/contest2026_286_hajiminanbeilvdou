# 演示视频脚本（≤5 分钟）

**目标时长 4:00**，mp4，用手机横屏或录屏 + 摄像头均可。
**镜头原则**：每次语音交互都要拍出「手指按住按钮」的动作——我们没有唤醒词，交互是 PTT。

---

## 拍摄前检查（重要）

1. 按 README 4.3 把全链路拉起来，确认 `voice_ready.sh` 输出 **READY**
2. 先把三个演示命令各试一遍，确认屏幕能正常出中文（避免现场卡壳）
3. 摄像头摆位：一个机位拍「手 + 板子屏幕」，一个机位（或录屏）拍电脑屏幕
4. 关掉手机通知/电脑弹窗
5. 板子供电用 5V/2A（仅 USB 供电时屏幕可能不亮）

---

## 分镜表

### 0:00–0:25 开场（录屏 + 字幕）

**画面**：黄山派板子特写旋转一圈 → 切到电脑录屏，终端里 `bash ~/voice_ready.sh` 滚出启动日志，
最后停在 `READY`。

**解说**：
> 这是黄山派，一块没有 WiFi 的 openvela 开发板。
> 我们让它变成了一个语音 Agent：**说话即命令，无人也干活**。
> 这条全自动化启动链看不到任何按键操作——复位、联网、拉起 Agent，全部由 PC 一条命令完成。

### 0:25–1:10 演示 1：语音下命令（手 + 屏幕同框）

**画面**：手指按住板子上的 PTT 键，说"**现在几点了**"，松手。等 1–2 秒，屏幕出现中文回答。
接着再按一次："**看一下设备的内存**"。

**解说**：
> 按住按钮说话，松手即识别。音频不走云端——
> 设备把声音压缩到每秒 8 KB，通过串口链路送到电脑做离线识别，再把命令回给设备执行。
> 屏幕上每一条回复，都是 Agent 真实执行的结果。

### 1:10–2:20 演示 2：主动巡检（核心差异化，重点展示）

**画面**：按 PTT 说"**请每两分钟巡检一次设备**" → 屏幕确认任务已建立 →
**加速剪辑**（画面角标"×N 倍速"）展示两三次自动出现的巡检结果，手完全离开板子。

**解说**：
> 现在开始，我什么都不做。
> Agent 会按计划自己醒来，读内存、查任务、看链路，把结果推上屏幕。
> 这是赛题最看重的「主动能力」——不是我问它才答，而是到点它自己汇报。
> 而且它不需要唤醒词：定时任务直接唤醒 Agent。

### 2:20–3:00 演示 3：断网降级（加分：演示不中断）

**画面**：拔掉电脑网线/关 WiFi → 再按 PTT 说一句"**现在几点了**" → 屏幕照常出结果。
角标字幕："网络已断开"。

**解说**：
> 现在把网络断掉。设备到电脑的链路走的是 USB 串口，不依赖互联网；
> 大模型通道自动切到本地剧本模式，演示继续。
> 这一点对展会、教学场景很重要——不会因为网络问题冷场。

### 3:00–3:40 技术速览（录屏 + 板子特写穿插）

**画面**：
- 终端里 `logs/Oliweitz/` 的 AI 开发日志滚动（体现 AI Coding）
- 板子屏幕上滚动的巡检气泡
- 快速闪过电路板 + 麦克风孔特写

**解说**：
> 这条链路背后是三件事：我们为这块板子写了 openvela 上**第一个可用的录音驱动**；
> 在每秒 12.7 KB 的串口带宽里用 G.711 压缩保住了语音质量；
> 并且修掉了平台上从 TLS 到技能系统的二十多处缺陷。
> 全过程用 Claude Code 开发，五个工作日，完整对话日志都在仓库 logs 目录里。

### 3:40–4:00 收尾（字幕卡）

**画面**：板子 + 屏幕最后一条巡检结果定格，叠加字幕。

**字幕 & 解说**：
> 黄山派语音主动 Agent
> 说话即命令，无人也干活
> 代码 / 部署步骤 / AI 开发日志：contest2026_286_hajiminanbeilvdou

## 应急方案

| 意外 | 处理 |
|---|---|
| 屏幕没反应 | 重跑 `bash ~/voice_ready.sh`，等 READY 重拍这一段 |
| 识别不准 | 靠近麦克风孔、放慢语速；或改用"看一下设备的内存"（短句成功率高） |
| 巡检一直不出 | 检查任务是否建立成功（屏幕应有确认），周期设 2 分钟即可，剪辑时加速 |
| 时间不够 | 砍掉 3:00–3:40 技术速览，保留三个演示即可 |
