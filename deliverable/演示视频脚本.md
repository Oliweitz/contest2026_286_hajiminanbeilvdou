# 演示视频脚本（≤5 分钟）

**目标时长 4:00**，mp4，用手机横屏或录屏 + 摄像头均可。

**⚠️ 用真实 API 拍，不要用 mock**：mock 的回答是预置台词（`让我查一下…`、`【设备资源】`），
评委一眼能看出是剧本。真实 API 会自己调工具、自己组织语言，才是作品的说服力所在。

**时延要有心理准备**：真实 API 每轮 **10~30 秒**（mock 只要 1 秒）。屏幕上会先出
「稍等，处理中…」，这是**正常的中间态**，剪片时可以加速，拍的时候别以为卡住了。

**开拍前务必先复位一次**（`bash ~/clean_rebuild.sh`）：设备侧有**应答缓存**，
之前用 mock 试过的句子会被缓存住，之后同样的输入直接返回旧回复、看起来还像在用 mock。

**两种交互方式（主打唤醒词，PTT 作兜底）**：

| 方式 | 怎么做 | 画面重点 |
|---|---|---|
| **唤醒词（主打）** | 说「**你好openvela**」，再说指令；或一口气说完「你好openvela，现在几点了」 | **手完全不碰板子**，体现"喊一声就唤醒" |
| **PTT 按钮** | **点一下**蓝色按钮开始录音 → **说话** → **再点一下**结束 | 手指点按的动作；**两次点击之间才是录音** |

⚠️ 唤醒词说单独一句时，屏幕会先出现「（已唤醒，请说指令）」——**这是设计好的提示，不是故障**。

## 拍摄前检查（重要）

1. 按 README 4.3 把全链路拉起来，确认 `voice_ready.sh` 输出 **READY**
2. 先把三个演示命令各试一遍，确认屏幕能正常出中文（避免现场卡壳）
3. 摄像头摆位：一个机位拍「手 + 板子屏幕」，一个机位（或录屏）拍电脑屏幕
4. 关掉手机通知/电脑弹窗
5. 板子供电用 5V/2A（仅 USB 供电时屏幕可能不亮）
6. **唤醒词要说连贯**：「你好openvela」中间**不要停顿**——停了会被切句器分成两段。
   识别器对 `openvela` 的转写不稳定（实测出现过 `open renline` / `ok v 乐` / `oppo via`），
   匹配规则认的是「你好 + 后面跟一段拉丁字母」，所以**照常说即可，不用刻意念准**。
7. **PTT 是点按切换**：点一下开始录音 → **说话** → 再点一下结束。
   ⚠️ **两次点击之间才是录音时间**——连点两下只会录到中间的空白（日志里表现为
   `[ptt] captured 0.5s` 然后"没听清"）。说完话再点第二下。
8. **要拍 2:20 的「断网降级」**：先 `bash ~/setup_llm.sh` 填好 API，再 `bash ~/proxy_restart.sh`
   （它带 `--fallback-mock`，断网才会自动降级）。只跑默认的 `voice_ready.sh` 本来就在用
   本地剧本模型，画面上看不出任何「切换」。
9. **⚠️ 设备有已知的平台缺陷会间歇性挂死**（NuttX 内核信号量竞态，见 README 第五节）。
   挂了的表现是屏幕冻结、ping 不通。**恢复只要一条命令**：
   ```bash
   bash ~/clean_rebuild.sh     # 约 1 分钟，不用拔插
   ```
   所以**一段一段拍**：每拍完一段先跑一次，再拍下一段。

## 分镜表

### 0:00–0:25 开场（录屏 + 字幕）

**画面**：黄山派板子特写旋转一圈 → 切到电脑录屏，终端里 `bash ~/voice_ready.sh` 滚出启动日志，
最后停在 `READY`。

**解说**：
> 这是黄山派，一块没有 WiFi 的 openvela 开发板。
> 我们让它变成了一个语音 Agent：**说话即命令，无人也干活**。
> 这条全自动化启动链看不到任何按键操作——复位、联网、拉起 Agent，全部由 PC 一条命令完成。

### 0:25–1:10 演示 1：语音下命令（手 + 屏幕同框）

**画面**：
1. **手完全不碰板子**，对着板子一口气说「**你好openvela，现在几点了**」→ 屏幕先出「稍等，处理中…」，
   十几秒后出现时间（**这一段剪辑时加速，或保留等待感——真实 AI 本来就要想一会儿**）
2. 再演示备用方式：手指点一下 PTT 按钮 → 说「**看一下设备的内存**」→ 再点一下结束

**解说**：
> 喊一声「你好openvela」，再说出指令，一两秒后结果就出来了——**全程不用碰板子**。
> 音频不走云端：设备把声音压缩到每秒 5.8 KB，通过串口链路送到电脑做离线识别，
> 再把命令回给设备执行。屏幕上每一条回复，都是 Agent 真实执行的结果。
> 不想开口的时候也可以用屏幕上的按钮：点一下开始说、再点一下结束。

### 1:10–2:20 演示 2：主动巡检（核心差异化，重点展示）

**画面**：点一下 PTT 说"**请每两分钟巡检一次设备**"（点一下开始、说完再点一下）→ 屏幕确认任务已建立 →
**加速剪辑**（画面角标"×N 倍速"）展示两三次自动出现的巡检结果，手完全离开板子。

**解说**：
> 现在开始，我什么都不做。
> Agent 会按计划自己醒来，读内存、查任务、看链路，把结果推上屏幕。
> 这是赛题最看重的「主动能力」——不是我问它才答，而是到点它自己汇报。
> 而且它不需要唤醒词：定时任务直接唤醒 Agent。

### 2:20–3:00 演示 3：断网降级（加分：演示不中断）

**画面**：拔掉电脑网线/关 WiFi → 再点 PTT 说一句"**现在几点了**" → 屏幕照常出结果。
角标字幕："网络已断开"。

**解说**：
> 现在把网络断掉。设备到电脑的链路走的是 USB 串口，不依赖互联网；
> 大模型通道自动切到本地剧本模式，演示继续。
> 这一点对展会、教学场景很重要——不会因为网络问题冷场。

### 3:00–3:40 技术速览（录屏 + 板子特写穿插）

**画面**：
- 终端里 `logs/Oliweitz/` 的 AI 开发日志滚动（体现 AI Coding）
- 板子屏幕上滚动的巡检气泡
- 快速闪过电路板 + 麦克风孔特写

**解说**：
> 这条链路背后是三件事：我们为这块板子写了 openvela 上**第一个可用的录音驱动**；
> 在每秒 12.7 KB 的串口带宽里用 G.711 压缩保住了语音质量；
> 并且修掉了平台上从 TLS 到技能系统的二十多处缺陷。
> 全过程用 Claude Code 开发，五天完成，完整对话日志都在仓库 logs 目录里。

### 3:40–4:00 收尾（字幕卡）

**画面**：板子 + 屏幕最后一条巡检结果定格，叠加字幕。

**字幕 & 解说**：
> 黄山派语音主动 Agent
> 说话即命令，无人也干活
> 代码 / 部署步骤 / AI 开发日志：contest2026_286_hajiminanbeilvdou

## 应急方案

| 意外 | 处理 |
|---|---|
| **设备挂死**（屏幕冻结、ping 不通） | 跑 `bash ~/clean_rebuild.sh`，约 1 分钟恢复，重拍这一段。**这是已知平台缺陷，不是操作错误** |
| 屏幕没反应但链路正常 | 先 `bash ~/bridge_restart.sh`，再 `bash ~/voice_ready.sh`，等 READY 重拍这一段。<br>（`voice_ready.sh` 不负责起桥；桥不在时 `demo_up.sh` 会直接报 `/dev/ttyHS` 缺失） |
| 按了没反应 | 确认**两次点击之间留出了说话时间**：点一下 → **说** → 再点一下。连点两下只会录到空白 |
| 喊了唤醒词没反应 | ① 中间别停顿（停顿会被切成两段）；② 屏幕没出现「（已唤醒）」就是没醒，再喊一遍即可 |
| 识别不准 | 靠近麦克风孔、放慢语速；或改用"看一下设备的内存"（短句成功率高） |
| 巡检一直不出 | 检查任务是否建立成功（屏幕应有确认），周期设 2 分钟即可，剪辑时加速 |
| 时间不够 | 砍掉 3:00–3:40 技术速览，保留三个演示即可 |
